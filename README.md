The current work primarily focuses on the design phase of a CCPS creation process. During this stage, the designer is occupied with defining the main elements of the system and establishing the basic rules governing how these elements will co-exist and communicate with each other, as the main leitmotiv of the CCPS is the ability of distributed elements to collaborate. The goal is to provide a general framework that clearly outlines the main steps that involved in the design process, as well as the necessary tools to support various stages of the design process. The tools developed in the framework of this PhD work are presented here.

The following tools and protocols were implemented to support various stages of this work:
1. Plain Text-based Requirements Processing Tool (PTRPT) – a human-AI collaborative tool designed to extract requirements from plain natural language text consists of two main components aimed at assisting designers in the requirements elicitation process. The first component leverages a Large Language Model (LLM) for requirements extraction, while the second one enables pattern extraction based on prior designer annotations and semantic text analysis. This second component enhances LLM performance and prevents the generation of incorrectly formulated requirements.
2. Discovery and Matching Tool (DMT) – to assist designers by: (i) matching the extracted user requirements with corresponding service categories, and (ii) identifying de-vices that can potentially be used to implement the services through both indirect and direct matching. Indirect matching starts by defining services as functional blocks, each with a high-level description, which are then matched with the high-level description of devices. The best matches are determined based on a calculated similarity metric. In contrast, direct matching takes a more straightforward approach by comparing the formalized properties of services and devices.
3. Concepts Mapping Tool (CMT) – a graph-based solution for tracking interrelation-ships among CCPS concepts and simplifying discovery. It leverages a semantic management component, primarily supporting the Design Time phase, and consists of Storage and Harmonisation components. The tool stores the CCPS structure as a connected graph, where nodes represent key elements and edges denote their relationships. This enables advanced reasoning, such as uncovering hidden connections as complexity increases. Designers can identify commonalities between services within the same Smart Environment (SE) and track service interactions during runtime.
4. Simple Collaborative Services Composition Protocol (SCSCP) – introduced to facilitate negotiations for forming collaborative services using the publish-subscribe paradigm. This is especially important given that services and devices may have different owners and be involved in ongoing activities, which may complicate their potential involvement in collaborative efforts.
5. Some other small tools/instruments and interfaces were implemented, including those ensuring proper deployment on the Node-RED platform and scripts for conflict resolution.
